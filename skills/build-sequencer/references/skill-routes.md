# Companion skills

These routes extend this procedure within the current task. Required steps apply
only under the stated condition; optional helpers do not widen authorization.
Prefer available client-native owners and read invocation limits before use.

| Skill | Relationship | When to load it |
|---|---|---|
| `behavior-proof` | required | When an implementation task reaches verification; not for a plan-only request. |
| `scope-grill` | optional | When an unresolved product choice changes the implementation. |
| `spec-implementer` | optional | When the user explicitly requests its spec/ticket implementation flow. |
| `temporal-flow-design` | optional | When the feature contains durable Temporal workflows. |
| `terraform-module-smith` | optional | When the requested deliverable includes Terraform modules. |
| `rn-expo-builder` | optional | When implementing a React Native/Expo feature. |
| `roadmap-slicer` | optional | When the finished plan should be published as Gitea issues with a roadmap. |

Load a listed skill only if the current client has it installed. Open the
selected `SKILL.md` and its needed references, resolving resources from that
directory. If a skill is not installed, say so; do not guess a tool or load
the whole group. Reuse already
loaded skills to avoid cycles. Report unavailable required checks explicitly.
